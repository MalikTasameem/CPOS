# بوابة اعتماد شبكة المراقبة قبل التسليم

## الحالة الحالية — ليست شهادة اكتمال

أُضيف منع بناء حزمة ترقية جديدة بدون نتيجة **Release** ناجحة ومطابقة لبصمة ملفات التطبيق وSQL والاختبارات. لا يغيّر هذا الحظر نسخة التشغيل الحالية ولا الحزم التاريخية التي سبق إنشاؤها.

الفحص يحصي العمليات من عقد VB الفعلي، ولا يعتبر ذكر اسم العملية في اختبار دليل نجاحها. نجحت مطابقة 111 عملية مع إجراءي بداية الطلب وكتابة الحدث في القاعدة المحلية. توجد تحويلات نص إلى `int` تحتاج معالجة/إثبات أمان، وفجوات في سيناريوهات SQL؛ لذلك **لم تُعتمد حزمة جديدة**.

هذه بوابة منع وتسليم قابلة للتوسعة، وليست إعلانًا أن كل عمليات النظام اجتازت الاختبار. الاختبارات التي تعتمد على بيانات قديمة أو تفتقد سيناريو فعلي تظهر كعائق؛ لا تتحول إلى نجاح أو استثناء صامت.

## التشغيل المحلي

استخدم **Windows PowerShell 5.1 — powershell.exe**؛ محلل SQL المستخدم هو ScriptDom الخاص بـSQL Server 2014، والمترجم VB14 المثبت مسبقًا. لا توجد مكتبة جديدة مطلوبة.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Invoke-AuditReleaseGate.ps1 -Mode Check
```

يشغّل 41 مجموعة اختبارات محلية واختبارات البوابة نفسها، ويختبر القيم تحت ثقافات `ar-LY/ar-SA/en-US/en-GB/fr-FR`. ينسخ ملفات الاختبار إلى مساحة مستقلة حتى لا تغيّر الاختبارات ملفات التشغيل أو نواتج اختبارات قديمة. لا يتصل بقاعدة بيانات افتراضيًا.

النتائج داخل مجلد جديد تحت `.tmp/AuditReleaseGate`:

- `AuditReleaseReport.md`: الملخص والعوائق وتغطية كل عملية.
- `AuditReleaseReport.json`: الدليل المقروء آليًا، وبصمة المصدر والسجلات.
- ملفات `*.log`: نتيجة كل مجموعة، مع الاستمرار في بقية المجموعات عند الفشل.

للفحص القرائي فقط، ضع اتصال SQL في متغير بيئة داخل عملية PowerShell الحالية ثم مرّر **اسم المتغير** بواسطة `-SqlConnectionEnvironmentVariable`. لا تضع كلمة المرور في سطر الأوامر أو الملفات أو Git. وضع `Check` لا يجيز البناء حتى لو نجح.

## الاختبارات الفعلية

1. استعد نسخة احتياطية موثوقة إلى قاعدة مستقلة بواسطة `New-AuditReleaseSandbox.ps1`. تتطلب الأداة `-ServerConnectionEnvironmentVariable` و`-BackupPath` المرئي لخدمة SQL؛ تستخدم اسمًا عشوائيًا `CPOS_AUDIT_GATE_<guid>` ولا تستخدم `REPLACE` أو تحذف قاعدة أو تفصل اتصالات المستخدمين.
2. طبّق ترقيات SQL المرشحة على النسخة المعزولة فقط. الاستعادة وحدها لا تُثبت أن الترقية جُرّبت. يجب اختبار مساري التثبيت الجديد وترقية النسخة التي لدى العميل قبل التسليم؛ لم تؤتمت البوابة حاليًا إعادة تركيب كل إصدارات العملاء.
3. ضع اتصال النسخة المعزولة في متغير بيئة، مثل `CPOS_AUDIT_CANDIDATE`، وشغّل:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Invoke-AuditReleaseGate.ps1 -Mode Release -SqlConnectionEnvironmentVariable CPOS_AUDIT_CANDIDATE
```

يُرفض تنفيذ اختبارات الكتابة على `CPOS` أو `CPOS_ACCOUNTING`. يلزم أيضًا وجود علامة ملكية النسخة المعزولة التي تضيفها أداة الاستعادة. تُترك النسخة المعزولة بعد الاختبار للتشخيص ولا تُحذف تلقائيًا؛ لا تفتحها في تطبيق CPOS ولا تستعملها كفرع تشغيل.

اختبار الوحدات الجديد يُنشئ بياناته بنفسه، ويختبر الإضافة والتعديل والحذف وإعادة الطلب وعدم تكراره، ووجود الطلب والحدث والتغييرات، والتراجع عن البيانات. يجري الاختبار تحت ثلاث ثقافات.

يجري مشغّل السيناريوهات القديمة نسخًا معزولة من اختبارات SQL الموجودة: يربط حراس اسم القاعدة وهوية المصدر بالنسخة المعزولة، ويقرأ الاتصال من الذاكرة بدل ملف إعدادات يحوي كلمة مرور. لا يعدّل خدمات الأعمال الأصلية. يضيف مراقب تغطية إلى **نسخة الاختبار فقط**، بعد إكمال الطلب بنجاح؛ لا يحتسب العملية إلا إذا وجد حدثها في SQL ونجحت مجموعة الاختبارات كاملة. لا يعطي الاختبار الفاشل أي تغطية، حتى لو نجحت خطوات سابقة فيه.

## شروط السماح ببناء الحزمة

- جميع مجموعات الاختبار المحلية ناجحة.
- كل عملية بالعقد معلنة في إجراءي SQL، ولا تظهر رموز عمليات غير معروفة في مواضع الفحص.
- لا يوجد تحويل مباشر غير مثبت الأمان للنص الخام في إجراءات المراقبة النهائية، بما فيه SQL الديناميكي المعروف. لا يتم فحص مقاطع البحث والاستبدال التاريخية باعتبارها إجراءات منفذة.
- كل عملية لديها سيناريو SQL ناجح، وليس مجرد اختبار محلي أو اسم موجود في ملف.
- لا توجد طلبات مراقبة غير مكتملة بالنسخة المرشحة.
- ملفات المصدر ثابتة طوال الاختبار، والتقرير مطابق لها عند البناء وعمره أقل من 24 ساعة وسجلاته لم تتغير.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ..\..\..\Database\Deployment\NetworkAuditUpgrade\Build-NetworkAuditUpgrade.ps1 -ReleaseReport 'المسار الكامل إلى AuditReleaseReport.json'
```

لا يوجد مفتاح `SkipTests` أو `Force` لبناء حزمة التسليم. تقرير فاشل أو تشخيصي أو قديم يمنع البناء قبل الكتابة على الحزمة الموجودة.

## حدود الفحص والإكمال المطلوب

- اكتشاف SQL الحالي محافظ: يشير إلى التحويلات التي تحتاج معالجة أو إثبات أمان، ولا يدّعي أن كل إشارة حادثة تشغيل مؤكدة.
- مطابقة أسماء العمليات لا تثبت وحدها صحة كل حقل أو صلاحية؛ لذلك يشترط وضع Release الاختبار الفعلي أيضًا.
- ليست هناك تغطية فعلية مكتملة للعمليات الـ111 بعد. الاختبارات القديمة تستخدم أحيانًا أصنافًا ووحدات وحسابات بأرقام ثابتة؛ يجب تحويلها إلى بيانات اختبار تنشئها بنفسها، كما في اختبار الوحدات الجديد. لا نغيّر توقع الاختبار ليمر على حساب إخفاء خلل.
- يجب إضافة اختبارات إنشاء/تعديل/إلغاء/حذف المسارات الحديثة، مع القيم الفارغة والحدود الرقمية والتواريخ ونوع المستخدم والصلاحيات وحقن فشل التسجيل والتراجع وإعادة المحاولة. عمليات لا تدعم حذفًا فعليًا تُختبر بالإلغاء أو دورة حياتها المسموحة، ولا نختلق عملية حذف.
- مسارات لا تستدعي المراقبة أصلًا، والاستعلامات الديناميكية العامة، وواجهات المستخدم لا تُثبت تغطيتها من استخراج أسماء العقد وحده؛ تحتاج مراجعة تغطية مستقلة واختبارات واجهة موجهة.
- التقرير ملف اعتماد محلي للمطور وليس توقيعًا أمنيًا ضد من يستطيع تعديل المصدر والتقارير. ينبغي أن ينتج نظام إصدار موثوق الحزمة والتقرير معًا.
- المسودات والعمل غير المتصل والعهد المؤجلة ليست ضمن التعميم الحالي.

## اقتراح استمرار العمل دون فقد التتبع — لم يُنفذ

الاقتراح المناسب هو **سجل أحداث خام مؤجل المعالجة داخل المعاملة نفسها (Transactional Outbox)**:

1. حفظ عملية الأعمال ومعها الحدث الخام: هوية الطلب والمستخدم والمستند والقيم السابقة واللاحقة بأنواعها، في نفس المعاملة.
2. بعد نجاح المعاملة، صياغة الوصف العربي والفهرسة والتفاصيل الثانوية في معالج مستقل قابل لإعادة المحاولة، مع منع التكرار بهوية الحدث.
3. فشل الوصف أو الفهرسة لا يلغي البيع بعد أن أصبح الحدث الخام محفوظًا. تظهر حالة «بانتظار معالجة سجل المراقبة» مع تنبيه للمسؤول وعدّاد للأحداث المتأخرة.
4. إذا فشل حفظ الأعمال أو السجل الخام الإلزامي نفسه، لا يجوز إعلان النجاح. هذا التصميم لا يعالج انقطاع SQL أو امتلاء القرص تلقائيًا، ولا يعادل نظام العمل دون اتصال.

لا نوصي بإضافة `Catch` يتجاهل فشل المراقبة ثم يحفظ الفاتورة: قد يسمح بعمليات بلا أثر قابل للإثبات. تغيير السياسة الحالية يحتاج تصميم انتقال واختبارات اتساق وصلاحيات واسترجاع منفصلة. لم تتغير سياسة الحفظ أو قاعدة التشغيل في هذا العمل.
