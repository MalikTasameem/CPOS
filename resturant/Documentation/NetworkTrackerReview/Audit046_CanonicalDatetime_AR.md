# إصلاح 046 — التواريخ الصحيحة في شبكة المراقبة

## السبب المثبت

أمكن إعادة إنتاج رسالة `CatalogItemRecord after-state differs from stored row` على نسخة اختبار معزولة من القاعدة، أثناء `Item.PlaceholderAcquired`.
الحقل المختلف في المقارنة هو `ItemDate`، وقيمته الفعلية الملتقطة `2026-11-07T19:40:40.2930000`.

التقاط البرنامج يرسل تاريخ SQL بصيغة ISO ذات سبع خانات كسرية. تحويل 044 المباشر
`TRY_CONVERT(datetime,c.AfterValue,126)` يعيد NULL لهذه الصيغة في SQL Server 2014.
لذلك يرفض الكاتب الحدث، وتتراجع معاملة تخصيص الصنف، ثم كان يمكن لمسار الحفظ أن يصل برقم غير مخصص ويظهر رسالة «بصمة/هدف الصنف غير صالح».
هذا ليس خطأ في إدخال المستخدم أو اسم الصنف. فحص الإعداد وحده لا يكفي لاكتشافه؛ ظهر عند تنفيذ الكاتب الفعلي.

### تأكيد حالة الإيصالات

أبلغ المستخدم أيضًا عن `ReceiptHeader after-state differs from persistent receipt data`، وأكد ظهورها قبل تطبيق 046.
أعيد إنتاج النص نفسه للإيصالين: قبض (3) وصرف (4)، بإرجاع مقارنات تاريخ الإيصالات العشرين مؤقتًا إلى صيغة ما قبل 046 داخل معاملة متراجعة على نسخة اختبار مملوكة فقط.
مع 046 نجح مسار الخدمة والكاتب الفعلي: الإنشاء، فتح التعديل، حفظ التعديل، والإلغاء لكلا النوعين؛ مع تسجيل رأس الإيصال والخزينة وإعادة الطلب دون تكرار.
لذلك لا تحتاج هذه الحالة ترحيلًا جديدًا أو تعديل `Receipt.vb`، ولا يُعطّل فحص التطابق.

## التغيير

- ترحيل `046_Audit_Canonical_Datetime.sql`: تحليل آمن إلى `datetime2(7)` ثم تحويل آمن إلى `datetime`، مع حد أعلى صريح يمنع قبول تقريب SQL Server 2014 لقيمة أعلى من آخر تاريخ صالح.
- تغطية تعبيرات التاريخ الثلاثة في الكاتب: 60 ظهورًا لـ `c.AfterValue`، وظهوران لـ `q.[QueueDateValue]`، وظهور واحد داخل SQL ديناميكي لـ `@value`.
- لم تتغير معادلات الأعمال أو بيانات الأصناف أو التواريخ المحفوظة، ولم يلغ فحص التطابق.
- شاشة `IM_ADD_New`: تعطيل الحفظ أثناء التخصيص، والخروج من شاشة الإضافة إذا فشل تخصيص الرقم، والتحقق من جاهزية الرقم في الزر وF12 ومسار الحفظ الداخلي.
- فاحص الإصدار يرفض الآن أيضًا التحويل المباشر الذي يعيد NULL لتاريخ صحيح، إلى جانب التحويلات التي قد ترمي استثناء.
- أضيف 046 إلى مصادر بناء أداة الترقية التالية. لم تُولّد حزمة إصدار كاملة ولم يُتجاوز شرط اعتمادها.

## التحقق المنفذ

- إعادة إنتاج الرسالة الأصلية قبل الإصلاح وتحديد الحقل المسبب بالشرط نفسه المستخدم في الكاتب.
- 120 اختبارًا محليًا لعقد دورة الصنف.
- 41 تحققًا SQL على قاعدة تحمل علامة `CPOS.AuditReleaseSandbox`: تخصيص رقم جديد، إعادة استخدام الصف غير المعتمد، الإضافة السريعة، الحفظ الكامل، تنظيف الصفوف، إعادة الطلب دون تكرار، ورفض تغيير الاسم/التاريخ أو تاريخ خارج المدى. جميع تغييرات الأعمال والمراقبة تراجعت.
- 1034 تحققًا محليًا لخدمة الإيصالات، و43 تحققًا حيًا مخصصًا للإيصالات على النسخة المعزولة: إعادة إنتاج الخطأ القديم، والعمليات الأربع للقبض والصرف بعد 046، وعدم تكرار الأحداث. تطابقت بصمات الجداول التسعة وتعريف الكاتب قبل الاختبار وبعد التراجع. لا تشمل هذه الاختبارات إيصالات العهد المؤجلة أو واجهة الجهاز البعيد.
- أضيف اختبار الإيصالات إلى `Test_Audit046_CanonicalDatetime.ps1` ليعمل تلقائيًا مع فحص 046. تقرير التنفيذ المنفصل: `.tmp/Audit046/receipt-01/Results.txt` في جذر المستودع.
- 1000 مدخل مللي ثانية يعاد تحويلها إلى قيمة SQL datetime نفسها، مع اختبارات NULL والنصوص غير الصالحة وحدود السنوات.
- فحص الإجراءات الأربعة عبر محلل SQL Server 2014؛ لا توجد نتائج تحويل غير آمن أو مباشر غير متوافق.
- اختبار ملف العميل نفسه: القاعدة الخاطئة، معاملة سابقة، اتصالات أخرى، غياب 044، فشل النسخة الاحتياطية، فشل مصطنع بعد ALTER مع التراجع، النجاح، ثم إعادة التنفيذ دون تكرار سجل الترحيل أو تغيير هوية المصدر.
- بناء منفصل ناجح، واختبار حواجز F12/الزر/الحفظ الداخلي دون فتح شاشة أو اتصال SQL.

## التسليم

ملف العميل المستقل:
`Database/Deployment/Audit046Hotfix/CPOS_Audit_046_Canonical_Datetime.sql`

يتطلب 044 أو أحدث، ولا يستبدل ترقية 045 أو صلاحية بطاقة العملاء. بعد إغلاق اتصالات CPOS/SSMS الأخرى، اختر القاعدة الصحيحة وطابق `@ExpectedDatabase`، ثم نفّذ الملف كاملًا وانتظر `UPGRADE SUCCESS`.
ينشئ نسخة احتياطية ويتحقق منها قبل التعديل. الترحيل تكراري آمن ولا يمس هوية قاعدة العميل.
يلزم بناء التنفيذي من المصدر المعدل لتطبيق حماية الشاشة؛ إصلاح المقارنة نفسه يقع في SQL.

**لم يُطبّق 046 على CPOS_ACCOUNTING الأصلية أثناء هذه المهمة، ولم تُستبدل نسخة التشغيل.**
هذا تحقق موجّه لهذا الإصلاح وليس شهادة اكتمال اختبارات كل عمليات المنظومة.
