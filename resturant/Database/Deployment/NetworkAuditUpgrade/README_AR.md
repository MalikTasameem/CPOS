# أداة ترقية شبكة المراقبة CPOS

هذه الحزمة مخصصة لتثبيت شبكة المراقبة الجديدة على قاعدة CPOS قديمة لا تحتوي جداول `Network_Audit_*`، أو لترقية تثبيت R2 المكتمل من المرحلة `043` إلى المرحلة `044`. الأداة لا تنسخ بيانات المراقبة من قاعدة أخرى، ولا تحذف سجلات المراقبة الموجودة.

الإصدار الحالي للأداة هو `2026.11.10.044-R3`. تعالج المرحلة `044` تحويلات التاريخ غير الآمنة في جميع مجالات المراقبة، ومنها بطاقات العملاء والموردين والمستخدمين، والمستندات، والمخزون، والرواتب، وتقسيم الطاولات. إذا اكتشفت الأداة إصدار R2/043 الموثق فإنها تطبق `044` فقط بعد أخذ نسخة احتياطية.

## الملفات التي تُرسل للزبون

- `CPOS_Network_Audit_Upgrade.ps1`
- `CPOS_Network_Audit_Upgrade.sha256`
- `Run_CPOS_Network_Audit_Upgrade.cmd`

ملفا `Template` و`Build` مخصصان للمطور ولا يلزم إرسالهما.

## طريقة التنفيذ

1. خذ نسخة من مجلد تشغيل CPOS الجديد المطابق لترحيلات قاعدة البيانات، ولكن لا تشغله بعد.
2. أغلق CPOS وVisual Studio وSSMS وأي برنامج متصل بقاعدة الزبون.
3. ضع الملفات الثلاثة في مجلد واحد على جهاز خادم SQL.
4. شغّل `Run_CPOS_Network_Audit_Upgrade.cmd`.
5. أدخل اسم خادم SQL، واسم القاعدة، وحساب `sysadmin`.
6. راجع الخادم والقاعدة الظاهرين، ثم اكتب `UPGRADE`.
7. لا تفتح CPOS حتى تظهر رسالة نجاح التحقق النهائي.
8. انقل نسخة CPOS الجديدة المطابقة، ثم افتح النظام واختبر شاشة المراقبة.

الأداة تنشئ نسخة احتياطية كاملة `COPY_ONLY` بجانب ملف بيانات القاعدة افتراضيًا، ثم تتحقق من صلاحية ملف النسخة. إذا أردت مسارًا آخر شغّل ملف PowerShell مع الباراميتر `-BackupDirectory`، مع ملاحظة أن المسار يجب أن يكون مرئيًا لحساب خدمة SQL Server.

## ضمانات الأداة

- تتحقق من بصمة ملفات SQL المضمّنة قبل الاتصال بالقاعدة.
- تتطلب SQL Server 2014 أو أحدث وحساب `sysadmin`.
- لا تغلق جلسات المستخدمين بالقوة؛ تتوقف إذا وجدت اتصالًا آخر.
- عند التثبيت الجديد تطبق المراحل `002` إلى `044` بالترتيب، مع استبعاد ملفات الاختبار والتراجع والمرحلة التجريبية القديمة `004`.
- عند وجود إصدار R2/043 مكتمل وموثق تتحقق من عدد وبصمات ترحيلاته، ثم تطبق `044` فقط.
- تستخدم معاملة خارجية واحدة؛ إذا فشل أي فحص أو إجراء ترجع جميع تغييرات الترقية.
- تسجل المراحل الناجحة في `dbo.CPOS_Database_Migration`.
- تنشئ `SourceId` جديدًا وفريدًا لهذه القاعدة ولا تستخدم هوية قاعدة التطوير.
- إذا وجدت تثبيتًا جزئيًا أو إصدارًا أقدم من قاعدة R2/043 المعتمدة، تتوقف ولا تحاول إجباره.
- يمكن تشغيلها مرة ثانية بأمان؛ إذا كان الإصدار `044` مثبتًا بالكامل فلن تغيّر شيئًا.

## فحص الحزمة دون قاعدة بيانات

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\CPOS_Network_Audit_Upgrade.ps1 -Action PackageCheck
```

## فحص قاعدة مثبتة

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\CPOS_Network_Audit_Upgrade.ps1 -Action Validate
```

لا تستخدم هذه الأداة لاستنساخ فرع جديد من قاعدة تحتوي شبكة المراقبة مسبقًا؛ النسخة المستنسخة تحتاج إعادة إصدار هوية المصدر بإجراء منفصل ومدروس.

## بوابة بناء الحزم الجديدة

أصبح `Build-NetworkAuditUpgrade.ps1` يتطلب `-ReleaseReport` من فحص Release ناجح ومطابق للمصدر الحالي. لا يكفي فحص `PackageCheck` أو نجاح الاختبارات المحلية وحدها. راجع `Documentation/NetworkTrackerReview/ReleaseGate/README_AR.md`؛ ما زالت هناك فجوات اختبار تمنع اعتماد حزمة جديدة. هذا لا يلغي الحزم التاريخية الموجودة ولا يغيّر قاعدة تشغيل العميل.
