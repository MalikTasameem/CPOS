# AGENTS.md

## تعليمات عامة للمشروع

- اقرأ الكود الحالي قبل أي تعديل.
- لا تعدل أي ملف بدون توضيح سبب التعديل.
- قبل التعديلات الكبيرة، اعرض خطة مختصرة.
- حافظ على نفس أسلوب كتابة الكود الموجود في المشروع.
- لا تغيّر أسماء الجداول أو الأعمدة أو الكنترولات إلا عند الطلب الصريح.
- لا تضف مكتبات جديدة إلا بعد توضيح السبب.
- بعد أي تعديل، راجع أخطاء البناء والأنواع والقيم الفارغة.

## قواعد قاعدة البيانات

- قاعدة البيانات SQL Server.
- لا تستخدم أوامر غير متوافقة مع SQL Server 2014 إلا إذا طُلب ذلك.
- لا تغيّر هيكل الجداول بدون طلب مباشر.
- عند كتابة Stored Procedure، استخدم أسماء واضحة للباراميترات.

## قواعد VB.NET WinForms

- افصل كود التصميم Designer عن Code Behind.
- لا تغيّر أسماء الكنترولات الموجودة إلا عند الطلب.
- عند التعامل مع DataGridView، تحقق من وجود الأعمدة والقيم الفارغة.
- تعامل بحذر مع ComboBox.SelectedValue.
- عند كتابة واجهة جديدة، اجعل التصميم مستقلاً عن كود التشغيل.
- أي Label غير رئيسية وتكون متعلقة بإدخال نص مثلا يكون نوع خط بها Segoe UI .
- أي Textbox يكون نوع الخط Segoe UI Semibold
- أي gridview يكون نوع الخط Segoe UI Semibold للبياانات و Segoe UI لرأس الأعمدة وعناوينها
- أي Buttons يكون نوع الخط Segoe UI Semibold
- أي ComboBox يكون نوع الخط Segoe UI Semibold
- أي Datetime Picker يكون نوع الخط Segoe UI Semibold



## قواعد ASP.NET Core

- تحقق من صلاحيات المستخدم قبل Add / Edit / Delete.
- سجّل العمليات المهمة في LogHistories باللغة العربية.
- استخدم GetUserId و HasPermission إذا كانت موجودة في المشروع.
- لا تغيّر أسماء DTOs أو Models إلا عند الحاجة الواضحة.

## قواعد Laravel

- حافظ على بنية Controller / Model / Blade / Livewire الحالية.
- لا تغيّر أسماء Routes إلا عند الطلب.
- عند تعديل Blade أو Livewire، انتبه للتوافق مع Alpine.js و wire:model.
- لا تغيّر أسماء الجداول أو العلاقات بدون طلب مباشر.

## أسلوب الإجابة المطلوب من Codex

- اشرح الملفات التي ستتأثر قبل التعديل.
- نفّذ أقل عدد ممكن من التغييرات.
- بعد التعديل، اكتب ملخصًا لما تغيّر.
- اذكر أي أوامر يجب تشغيلها للتحقق من المشروع.
